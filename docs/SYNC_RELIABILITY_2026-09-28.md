# 同期・読み込み信頼性の修正記録

作業日: 2026-09-28〜29。対象: `dev` / 基点 `f75467c`。本番・開発のD1共用はユーザー指定の運用方針として維持し、`wrangler.toml` と既定接続先は変更していない。

## 症状と修正

| 症状 | 確認した原因 | 修正 |
|---|---|---|
| 同じファイルを開いてもクラウドの書籍と紐づかない | メタデータに `cloudBookId` が欠け、mapのキーにIDがあっても値だけの検索で一致を利用できない | 保存時にIDを付与し、旧データはmapのキーから補完。通常ファイル選択と保存済み書籍の照合処理を共通化 |
| 読み込みが一度目に始まらないことがある | OSピッカーからfocusが戻って300ms/3秒でキャンセル確定。クラウド提供元の準備が遅いと後続changeを捨てる | focusタイマーを廃止し、inputのchange/cancelで確定。同一ファイルの再選択もリセットして受理 |
| 同期済みなのに先頭が開く、ジャンプ選択が出ない | 初期認証の復元待ち不足、構造化EPUB位置の比較不備、クラウド選択後も新旧比較でローカル位置を維持する経路 | Firebase認証復元を待機。位置全体を比較し、明示的なクラウド選択を適用。読み込み中は旧リーダーの位置を送らない |
| 端末切替で進捗が戻る | 復帰時に取得より先に古い画面を強制保存・送信。変わっていない位置の更新日時も進む | 復帰は取得を先に実行し、必要な位置選択とジャンプを行う。同じ位置の保存は更新日時を進めない |
| しおりが届かない、消したしおりが復活する | 書籍メタデータの更新のみを取得条件に使用。しおり全体の置換と削除情報の欠如 | サーバーの状態更新版を別に返す。しおりを位置キー単位でマージし、削除時刻を同期 |
| 読み込み前の待ち時間が長い | 全書籍の状態同期をファイルオープンの前に待機 | オープン時はインデックス照合と対象書籍の状態取得に限定。メタデータ送信は表示後に開始 |
| 通信失敗後にライブラリ登録が届かない | メタデータを送信成功後にだけローカル保存する経路 | 先にローカル保存し、`cloudIndexDirty` に未送信情報を保持。次回同期で再送 |

ローカル位置とクラウド位置に1%以上の差がある場合に選択メニューを出す既存方針は維持する。しおりから指定位置を開く場合は、その明示的な位置を優先する。

## 同期のデータ契約

- `cloudBookId`: メタデータにも必ず保持。旧JSONのキーから補完する。
- `progressUpdatedAt`: 読書位置の更新時刻。しおりの追加・削除だけでは位置の優先順位を変えない。
- `bookmarkTombstones`: 位置キー→削除時刻。同時編集時の古いしおりの復活を防ぐ。
- `updatedAt`: 進捗・しおり・削除を含む状態全体の最大更新時刻。
- `stateUpdatedAt`: インデックス取得時にWorkerが付けるサーバー保存時刻。クライアントの `stateVersion` と比較して必要な状態を取得する。旧Workerがこの値を返さない場合は状態を取得する。
- `/sync/index/pull`: クライアント時刻をカーソルとする差分取得をやめ、現在のインデックス全体を返す。既存クライアント向けの `data` 形式は維持する。
- `/sync/state/push`: マージ後の `state` も返す。古い位置で新しい位置を置換せず、独立したしおり変更を取り込む。

`workers/src/index.js` はSQLiteの条件付きUPDATE/INSERTと再試行でJSONの読取・書戻し競合を検知する。異なる書籍の同時登録や、同一書籍のしおり同時追加で、後着の書込みが他方を丸ごと消さない。

タイトルだけを根拠とする自動削除・統合を止めた。既存の重複IDはデータを保持し、将来サーバー側で全状態を安全に移行できるまでは自動削除しない。

## その他の修正

- **認証**: Firebase公開鍵のキャッシュとRS256署名検証を追加。期限・発行時刻・認証時刻・audience・issuer・subjectも検証し、取得失敗時は認証を通さない。[Firebaseの検証要件](https://firebase.google.com/docs/auth/admin/verify-id-tokens)を参照。
- **API**: POSTのストリーム読取りにサイズ上限を追加。500応答に内部スタックを含めない。プロキシはHTTPS限定とし、未検証のリダイレクトを追わない。
- **送信容量**: `keepalive` は60KiB以下の送信に限定する。大きいライブラリの更新は通常のfetchで送り、ブラウザのkeepalive容量制限による失敗を避ける。
- **PWA**: 実行時JS/CSS/WASMを生成スクリプトで列挙し、欠落パスを生成時に検出。存在しないCSS参照を除去。`?v=` を除いたローカルキャッシュ照合、取得成功時の保存、オフライン時の設定読込みを追加。キャッシュ名を `bookreader-v53` に統一し、他アプリのキャッシュを一括削除しない。
- **OS共有**: 相対URLの `Response.redirect` を、リクエストURLから構築した絶対URLへ変更。
- **Web小説**: 許可したHTML要素から新しいDOMを構築し、イベント属性・危険なURL・埋込み実行要素をコピーしない。通常の既存viewerにもscrollリスナーを登録。
- **Android署名**: パスワードの直接記載を削除。`BOOKREADER_KEYSTORE_PASSWORD` を利用し、apksignerも環境変数から取得する。
- **CI**: 重複本番デプロイを検証ワークフローへ変更。本番・開発のWorkerデプロイ前に回帰テストを実行。
- **SQL移行**: 未適用の0003は旧テーブルをバックアップ名へ変更して行をコピーする。既に適用済みの0003は再実行されない。旧 `data` と現行カラムの両構成をテスト。サポート対象は0001と同じカラム順序で、未知のスキーマは事前確認が必要。
- **資料**: READMEの開発ガイドのリンクを修正し、未実装のNotion OAuthを完成機能とする記載を修正。
