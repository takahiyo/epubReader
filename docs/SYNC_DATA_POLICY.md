# 同期データの方針（2026-10-04）

各端末で利用者が同じ書籍ファイルを選び、クラウドでは読書状態を引き継ぎます。書籍本体の転送は行いません。送信許可項目は `assets/js/core/cloud-payload.js` に集約し、クライアントの送信直前とWorkerの保存直前に適用します。

| データ | 方針と目的 |
| --- | --- |
| 書籍ID、書名、著者、ファイルの識別値 | 同じ書籍の照合と本棚表示に使用。書名設定によってはファイル名が書名になるため、書名は機微な情報を含み得る |
| 章番号・本文区間、画像番号、Web小説の話数・位置、進捗率 | 画面ごとに変わるページ番号に依存せず続きから開く |
| しおりの位置、利用者が付けた名前、日時、端末ID・色、削除記録 | しおりの表示・端末別色分け・競合解決・削除の維持に使用 |
| 書字方向、閲覧方式、文字サイズ | 読書環境を引き継ぐ |
| 本文断片、検索語、任意の追加フィールド、ローカルパス、OS・ブラウザー情報 | 送信しない |
| APIキー、OneDriveトークン、接続先、その他の端末固有設定 | 旧同期先への保存データ全体送信から除外。同期APIの認証に必要なidToken自体は従来通り認証リクエストに付ける |

本文断片は送信データのコピーから除き、端末内の進捗・しおりは変更しません。同一ファイルの章・本文区間を端末間で復元します。文字列照合による補助は端末内で利用できますが、別端末への新しい同期データには含まれません。内容の異なる版・再編集された書籍の引き継ぎは保証しません。

しおりの識別キーは本文断片を含めず、旧形式の削除記録も同じキーへ変換します。本文付きの旧しおりと新しいしおりが重複したり、削除済みのしおりが復活したりすることを防ぎます。

旧OneDrive・pCloud・汎用エンドポイントの同期経路も、許可した読書データと少数の表示設定だけを保存します。全ローカル設定・閲覧履歴・任意の属性を丸ごとバックアップする動作は終了します。既存のローカルデータやリモートファイルを削除する操作は実施していません。

## 既存のクラウドデータ

今回の変更はdevブランチに反映し、開発用Workerへデプロイ済みです。本番用Workerは未デプロイです。サーバー側の変更を反映した後、更新した書籍の状態と書籍情報を保存するときに、旧本文断片・不要項目も保存対象から除きます。未更新の書籍、以前のバックアップ、他の同期先に残っている旧データは、自動的に一括削除されません。一括消去は別途の移行・管理作業になります。

## 検証

送信データに本文断片と認証設定が残らないこと、ローカル本文断片が変更されないこと、旧削除記録の互換性、実際の送信リクエスト、SQLite上の旧Workerデータ更新を検証しました。既存の位置復元・認証・同期競合テストと合わせて25件が通過しています。
