# EPUBシームレス表示の文字位置（2026-10-07）

## 責務・呼び出し元

`assets/js/core/epub-scroll-anchor.js` はDOMの文字Rangeを使って位置を捕捉・復元する。外部サービス・ストレージへアクセスしない。`ReaderController` のgetPageLocator、getCurrentVisibleText、DOMジャンプ、ResizeObserverから利用する。設定・セレクタは`SCROLL_ANCHOR_CONFIG`、本文区間の単位は既存の`READER_CONFIG.TEXT_SEGMENT_STEP`を使用する。

## 位置表現

`spineIndex` は表示中の文字が属する章、`segmentIndex` は同章内の従来の5文字区間（画像等は1区間）。結合表示でも章ごとに区間を数え直す。章の途中から始まる表示断片には`data-segment-start`を付け、元の章の区間番号に戻す。

`viewportOffset` はその文字・画像の上端と表示領域上端のピクセル差。端末内だけに保存し、クラウド送信schemaには加えない。異なる端末でも本文区間の位置は引き継げるが、同じ画面内高さを共有しない。本文断片も従来どおり端末内のみ。旧位置にoffsetがなければ本文区間を上端へ合わせる。

## 復元と競合

文字Rangeへ即時スクロールする。CSSのsmooth設定を引き継ぐscrollTop代入では、移動前の位置を再保存するため、behavior=instantを明示する。描画予約後の新しいジャンプはnavigation世代で保護する。別のDOMへ切り替わった古い描画フレームは実行しない。

再組版は位置合わせの描画フレームが完了するまで保存抑制を維持する。viewportが変わった直後の位置計測では旧レイアウトの最後の有効位置を使う。フォントサイズ変更も、フォント・paginationの変更前に位置を捕捉する。

復元直後の遅延画像等のサイズ変更は同じ文字位置へ補正する。利用者がスクロールした後はその復元予約を終了し、過去の位置へ引き戻さない。

## 検証・残件

Chromeの実際のRange・ResizeObserverで、長い段落、結合章の途中、非ゼロ区間から始まる表示断片、幅変更、smooth指定、描画予約とジャンプの競合、遅延サイズ変更、利用者のスクロール、画像途中の復元をテストする。実際のアプリによるEPUB読込・リサイズと既存の同期OFF/復帰テストも対象とする。

Android実機でのアプリ切替・OS破棄は未検証。独立した軽量checkpointと保存頻度調整は未実装。本文区間の精度は従来の5文字単位を維持する。異なる版の本文・複雑な表示を持つ全EPUBでの位置復元を保証するものではない。
