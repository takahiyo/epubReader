# 読書UIの更新と次の改善候補（2026-10-04）

## 今回の変更

読書面に散在していた操作を、単一の「読書メニュー」にまとめました。ライブラリ・目次・しおり・テキスト検索・設定を常に同じ順序で並べ、書籍を開く操作や表示方向・テーマ・言語は折りたたみグループにまとめています。

- PC・タブレットは中央のパネル、幅640px以下は画面下のシート。DOMとイベント処理は共通で、CSSのみで配置を変えます。
- 主要操作は44px以上。ローカルSVGの線画アイコンに説明ラベルを付け、明暗テーマ・オフライン表示に対応します。
- 文字サイズとズームは同じ領域に配置。画像書庫では文字サイズ操作を隠し、拡大中は倍率と解除のみ表示して本文へのパン操作を妨げません。
- 操作領域はスクロール可能。短い横画面や大きなUI文字ではパネル全体もスクロールでき、長い書名は省略表示で横方向のはみ出しを防ぎます。
- 閉じるボタン、Tab移動の制御、Escapeで閉じる処理、展開状態の読み上げ属性を追加しました。同期の選択が必要なダイアログはEscapeで選択を省略させません。
- 進捗表示の古いローカルフラグへの依存を除き、実際の表示状態に基づいて更新します。進捗バーは線を細く保ったまま操作領域を広げ、しおりマーカーに操作名を付けています。

新しい配置の上書きは `assets/css/23-reader-controls.css` に集約しています。画面別のリーダー実装、外部UIライブラリ、書籍転送APIは追加していません。

設計の参考はW3Cの[Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)、[Focus Order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)、[Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)です。44pxは本アプリの操作サイズとして採用した値であり、今回の変更だけでWCAG全項目への適合を保証するものではありません。

## 検証

`tests/reader-controls-ui-cases.mjs` を既存のChrome検証に組み込みました。EPUBとCBZの実際の読書メニューで次を確認します。

- 320×568、390×844、568×320、768×1024、1024×768、1440×900の6サイズ、日本語・英語、明暗テーマ。
- パネルの画面内への収まり、横方向のはみ出し、主要操作の順序と44px以上のサイズ。
- 全グループ展開後も各ボタンをスクロールして操作できること。
- UI文字200%と長い書名、Tabの巡回、Escapeで閉じる処理、設定への移動、進捗表示の更新。
- CBZの拡大・倍率スライダー・解除、および読書面への入力の透過。
- 新しいCSS・フォーカス制御モジュール・SVGを含むオフライン取得。

認証とクラウドAPIは模擬データを使用します。実機Safari/iPadOSでのタッチ操作と読み上げは、Chromeでの画面サイズ検証とは別に確認が必要です。

## 次の改善候補（優先順）

1. **「続きから読む」を中心にしたライブラリ**：最近読んだ書籍を最初に出し、書籍ごとに「この端末で読める」「ファイルの選び直しが必要」「同期中／失敗」を表示。端末を替えた時の次の操作を明確にします。
2. **設定の整理**：「この書籍の表示」「端末の操作」「アカウントと同期」にまとめ、頻用項目を先に表示。既存の設定パネルを整理します。
3. **保存容量の管理**：端末内の書籍サイズ・使用容量を表示し、本体だけを削除して進捗やしおりを残す操作を明示。スマートフォンの容量不足と再ダウンロードの判断を助けます。
4. **読書面の操作案内**：初回に短いタップ領域の案内を表示し、設定から再表示可能にする。主要操作を探す負担を減らします。

最優先は1です。今回の読書メニューとつなげることで、端末間で読み続ける目的に直接役立ちます。
